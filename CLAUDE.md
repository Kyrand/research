# Repository Overview

This is an AI research repository where each top-level directory is a self-contained research project carried out by an LLM tool (usually Claude Code). Every line of text and code is written by an LLM.

## Repository Structure

```
research/
├── CLAUDE.md              # This file — instructions for AI assistants
├── AGENTS.md              # Core workflow instructions (included above)
├── README.md              # Auto-generated project index (do NOT edit manually)
├── requirements.txt       # Python deps: cogapp, llm, llm-github-models
├── .gitignore             # Standard ignores
├── .github/workflows/     # CI: auto-updates README.md on push to main
├── example-code-project/          # Template: code-heavy research project
├── example-documentation-investigation/  # Template: docs-heavy research project
└── <project-name>/        # Each research project is a top-level directory
    ├── README.md           # Final report (required)
    ├── notes.md            # Process log — append as you work (required)
    ├── _summary.md         # Auto-generated — NEVER create this manually
    └── ...                 # Code, diffs, artifacts as needed
```

## Research Project Workflow

1. **Create a new top-level directory** with a descriptive name for your investigation
2. **Create `notes.md`** immediately and append to it as you work — track what you tried and what you learned
3. **Do your research** — investigate, write code, analyze findings
4. **Write `README.md`** as the final report summarizing your investigation
5. **Commit only your folder** with its contents

## Project Types

### Documentation Investigation
For research that focuses on written analysis:
- `README.md` + `notes.md` (minimum)
- Code snippets or extracted artifacts as separate text files

### Code Project
For research that involves writing and testing code:
- `README.md` + `notes.md` (minimum)
- Python source files following standard conventions
- Tests placed alongside source code (pytest style)
- Build configuration when relevant

## Key Rules

### What to include in commits
- Your `notes.md` and `README.md` files
- Any code you wrote
- If you modified an existing repo, save `git diff` output as a file — not the full repo
- Binary files only if < 2MB

### What NOT to include
- Full copies of code fetched during investigation
- `_summary.md` files — these are auto-generated by CI
- External dependencies (don't vendor them)
- `node_modules/`, `__pycache__/`, `.DS_Store`

## CI/CD Pipeline

A GitHub Actions workflow (`.github/workflows/update-readme.yml`) runs on every push to `main`:
1. Checks out the repo with full history
2. Installs Python 3.11 and dependencies from `requirements.txt`
3. Runs `cog -r -P README.md` to regenerate the project index
4. Uses `llm` CLI with `github/gpt-4.1` to generate `_summary.md` for each project
5. Auto-commits updated `README.md` and `_summary.md` files

The root `README.md` uses cogapp templates to automatically list all research projects sorted by date, with AI-generated summaries.

## Development Environment

- **Python**: 3.11+ (used by CI)
- **Testing**: pytest (for code-heavy projects)
- **README generation**: `cogapp` — run locally with `cog -r -P README.md`
- **LLM summaries**: `llm` CLI with `llm-github-models` plugin

### Local README update
```bash
pip install -r requirements.txt
cog -r -P README.md
```

## Code Conventions

- Python code follows standard conventions (PEP 8)
- Tests use pytest with plain `assert` statements
- Test files named `test_*.py` alongside the modules they test
- Docstrings on public functions
- Minimal dependencies — keep projects self-contained
